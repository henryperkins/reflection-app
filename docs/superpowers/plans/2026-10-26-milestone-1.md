# Milestone 1 local foundation implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for bounded implementation tasks and independent review. Checkboxes record completed work.

**Goal:** Build and verify a local synthetic foundation implementing deterministic tarot plans and guarded D1 publication.

**Architecture:** A fresh sibling application repository imports the approved specification at `278d5fdb1636225887220368fbef52dc0d7ab889`. Source contracts, migrations, publication guard and field registry become authoritative; documentation copies and HTTP/model projections are generated and checked for drift. Domain code has no storage/network dependencies; a synthetic-only D1 prototype exercises actual Worker bindings and an intercepted writer.

**Tech stack:** Strict TypeScript, Hono, React, Vite, Zod, Wrangler/workerd D1, Vitest with the current Cloudflare plugin, Python SQLite artifact checks.

**Spec:** `docs/architecture/IMPLEMENTATION_PLAN.md` Milestone 1; `GENERATION.md`, `VERIFICATION_PLAN.md`, `DOMAIN_CONTRACTS.ts`, `schema.sql` and `publication_guard.sql` in the same directory.

## Global constraints

- Synthetic local data only; no credentials, real records, paid inference, remote database, or deployment.
- One npm project and lockfile; strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes.
- Three positions: situation, tension, possibility. 78-card RWS identity; no replacement. HMAC-SHA256 Fisher–Yates rejection sampling per GENERATION.
- Database execution clock controls strict lease/absolute expiry; equality is expired. Actual D1 batches must roll back on assertion failure.
- A unique owner/intent and unique dispatch/publication prevent duplicated work. Current ownership, permission, content, source and key guards remain enforced.
- All seven facts and exactly three approved-status synthetic sources feed the same plan used by model projection and deterministic composition. Test approval metadata never constitutes human production approval.
- Verification fails on schema or field-registry drift and any unexpected network call; nine-minute hard deadline. Production release stays disabled pending milestone 2 qualifications.

## Review focus

1. A rejected random word must be retried without modulo bias; pin boundary vectors in Task 2.
2. Source/card/position/orientation mismatches must fail before rendering; cover malicious and missing canon in Task 2.
3. Duplicate retries with changed payloads must conflict, and separate owners must never share a result; Task 3.
4. Expiry or revocation after worker eligibility sampling must abort every publication write; Task 3.
5. A new private column or generated schema edit must cause verification failure without rewriting expected policy; Task 4.

## Execution decisions

- Use a separate local repository `../reflection-app`, because the approved architecture repository is a specification package. No remote repository is created by this milestone.
- Domain and database tasks have disjoint file ownership and can proceed concurrently after the common scaffold. Root owns configuration and verification integration.
- The browser shell identifies a development foundation; it is not a first-user experience. Browser identity/accessibility and live provider qualification remain milestone 2.
