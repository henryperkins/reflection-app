## Automated local gates

- **`npm run verify` / `npm run test:browser`:** Playwright 1.64.1, Chromium 156.0.8078.4, headless Linux, Node 26.12.1. Normal canonical origin: `http://localhost:8787`. WebAuthn uses virtual CTAP2 authenticators. No paid/provider calls or local credentials are used.
- **`npm run test:journey`:** Chromium 156.0.8078.4, Firefox 157.0 and Playwright WebKit 27.2. The dedicated config runs the signed-in journey and 320/390/768/1280 px × light/dark layout cases. Install all three Playwright engines and their OS libraries first; the HTTPS transport helper also needs OpenSSL.
- **Native Chromium page zoom:** `journey-native-zoom.spec.ts` launches a disposable full Chromium profile (Playwright's `chromium` channel), loads the test-only extension under `tests/fixtures/native-zoom/`, and sets `chrome.tabs.setZoom(..., 2)`. It resizes the actual browser window to 640/780/1536/2560 pixels, asserting effective viewports of 320/390/768/1280 CSS pixels, DPR 2, CSS zoom 1 and visual-viewport scale 1. No device-scale or viewport emulation is active. The extension does not ship with the app. This covers headless Linux Chromium's real page-zoom mechanism, not Safari/Firefox zoom menus, OS text scaling or AT usability.
- **Forced colors:** `journey-forced-colors.spec.ts` runs Chromium and Firefox with forced-color emulation at all four widths and both color-scheme preferences. It exercises checked/unchecked/focused controls, complete sources, reflection/stance saving, AI-off return and system-colored disabled controls. Firefox on Linux keeps its default light forced palette even with a dark preference; that is not a second Windows contrast theme. WebKit is excluded from this specific probe because its Linux override reports the media query but does not substitute the system palette. The ordinary WebKit layout/journey gate still runs.
- The cross-engine harness uses `https://localhost:8843` with a short-lived self-signed test certificate and `ignoreHTTPSErrors`. `scripts/browser-journey-https.ts` proxies only to the synthetic loopback Worker, translating its local Origin/Referer to the Worker's canonical origin. **Secure, HttpOnly and SameSite cookie settings are not weakened.** WebKit does not send these cookies over HTTP loopback, so HTTP-only testing is not representative even for the signed-in UI.
- Cross-engine sessions are provisioned with Chromium's virtual authenticator on the canonical synthetic origin, then copied into the test browser's cookie jar. This proves actual signed-in UI/API behavior, not Firefox/WebKit registration or hosted RP/origin acceptance. Firefox/Chromium prompt-cancellation cases use a deliberate `NotAllowedError`. This Linux WebKit build has no WebAuthn credentials API; it exercises the real unsupported-browser error instead.
- Development servers are never reused by these gates. Verification requires a checkout without local dotenv/dev-vars files. When a personal instance occupies 8787, use a separate source snapshot and consistently remap its loopback harness origins; do not stop or change the personal instance.

## What is exercised

The full Chromium suite covers registration, complete recovery-kit download/acknowledgement, passkey sign-in, reauthentication/add/remove, last-factor controls, logout-all, recovery and exact saved-content reopening with AI off. Database tests independently enforce ownership, origin/counter checks, spent-code rejection, factor limits and competing enrollment. A database assertion is not a physical-authenticator result.

The portable journey checks keyboard photo selection/removal, preparation/completion announcements, full Meta/OpenAI/storage disclosures, progress live-region attributes, accepted-heading focus, Save, authored reflection/stance, Account entry/return, passkey error recovery, exact history reopening without another Start, reading deletion and Account deletion/focus return. Saved content and disclosures are asserted, not shortened to match a concept.

The layout matrix captures landing, recovery, empty/populated history, Account, empty/attached forms, photo/drawn reading details, expanded sources and reflection editing. Questions reach the current 500-character limit; filenames are long and contain no spaces. Separate comparison-capture probes use a 500-character unbroken question and a 244-character filename with a 240-character unbroken stem. The matrix asserts horizontal reflow, mobile heading/art separation, complete interpretations/synthesis/action/source text and unchanged saved content. CSS zoom at a 640 px viewport probes doubled rendering for reading and Account; it is **not browser-native zoom or OS text-size evidence**.

`artifacts/visual-pass/` retains first-batch screenshots, ARIA snapshots, per-layout overflow/image-choice evidence and the cross-engine JSON report. `artifacts/verify.json` binds each standard gate to its tested snapshot. Skipped/flaky tests cannot close that gate. Screenshot-only health and two-passkey fixtures are documented separately; the actual backend remains synthetic and does not establish photo-recognition accuracy.

The accessibility follow-through is archived under `artifacts/accessibility-pass/`: standard/matrix receipts, refreshed ordinary matrix screenshots, and native-zoom/forced-colors screenshots with per-state window/viewport/DPR/zoom evidence. Native-zoom PNGs use the browser's zoom-adjusted capture coordinates and assert PNG dimensions; the initial Playwright full-page captures cropped the zoomed viewport and are not accepted visual evidence.
