# Persistence semantics and field coverage

The actual proposed DDL is [schema.sql](schema.sql). [COLUMN_REGISTRY.json](COLUMN_REGISTRY.json) enumerates **every column**, type/nullability/default, class, export rule and inherited table retention/erasure rule. Classes: P public, M sensitive metadata, E encrypted personal body, S secret verifier (hash only), K wrapped key. A field classified M is not safe to log just because it is not E. Public keys/credential IDs are M, not decryption secrets. Per-table policy applies to all columns unless the column's `export:never` overrides it. Registry generator was a one-time authoring aid; verification compares the fixed reviewed registry against DDL and never regenerates missing coverage to make a gate green.

All integer timestamps are trusted UTC epoch milliseconds; all wire timestamps UTC ISO. IDs are UUIDv4 validated at the service boundary; SQL enforces uniqueness and relationships. Account-encrypted bodies use versioned Ciphertext JSON envelopes stored as TEXT; deletion_jobs.target_enc instead caches the independently keyed RecoveryCiphertext defined in SECURITY_RESTORE. Authorization deadlines use the database execution clock, not a bound Worker timestamp. Encrypted plaintext is a closed versioned domain object, **not a generic facts blob**; basis table accepts tarot.v1 only. Crypto runtime checks nonce/tag/AAD/version and body size. Max encrypted cell1.5MiB, normalized legacy record192KiB UTF-8, ordinary model candidate64KiB, account20MiB. Storage byte counter is exact UTF-8 bytes of private encrypted columns plus bounded overhead reservation; serialize/encrypt before comparing increment in a fenced transaction. It is an admission estimate, not Cloudflare billing. Quota and financial accounting are separate tables.

Reserve at least1KiB overhead for every owned persisted row, in addition to encrypted UTF-8 bytes; decrement only when the row/body is actually removed. This conservative20MiB account cap bounds client export memory and is a chosen initial operating limit, revisited after measurement. Export100 records/page (still≤1MiB) with a60-minute snapshot ticket; client retains serialized UTF-8 chunks and releases parsed objects, aiming≤64MiB working memory. It does not buffer multiple complete JSON representations or silently persist export bodies offline. A completed user-initiated download is the explicit persistence exception.

Foreign-key ownership is deliberately redundant: `(owner_id, foreign_id)` references an equally unique owner/key on the parent. Cross-owner reads return404 before decrypt; writes cannot rely on untrusted IDs even where FKs exist. Fields with application-enforced equality above must be validated both at boundary and inside guarded write transaction where state can change. The registry's table default governs metadata deletion; keeping a reference shell never permits retaining body_enc, originalJsonText, selected fragment copies or plaintext hashes.

Pagination: history/revisits use descending `(created_at,id)` and matching composite index; no OFFSET. Request due scans filter the closed nonterminal states then `(next_run_at,id)` with an expired-or-null lease. Import items key `(batch_id,item_index)`; reflection history `(reflection_id,revision)`; editions `(owner_id,session_id,edition_number)`. All pages bounded, indexed and owner-qualified. After a concurrently removed row, next cursor continues ordered scan; no claims of frozen history. Exports are different: any data_revision change invalidates the ticket; a completed export is one consistent optimistic snapshot or an explicit conflict, never mixed revisions.

Compatibility: additive SQL schema expansion preserves N/N−1 decoders; encrypted envelopes independently versioned; domain discriminants select decoder, not shape guessing. Unknown version returns unavailable/upgrade error without overwriting. Content/prompt/validator/model policy hashes are retained on accepted body; model outputs locally validated against the captured schema and current policy before publication. Historical rendering uses accepted code-rendered text, not a new renderer synthesizing different facts. User annotations/revisions can change; accepted edition cannot, except explicit redaction. Imports remain unverified even if their JSON parses under a current schema.

Reference erasure ordering: fence then ledger intent/pass; revoke source grants, fence dependent nonterminal requests, erase snapshots/transmission/provenance and mark unavailable output where safe redaction is impossible; null session/basis/edition bodies while retaining referenced IDs; detach import alias tombstones, delete revisit/preview/raw copies; scrub cost linkage; account-wide deletion then removes owned tables and keys through cascades after detached ledger updates. Test FK cycles with actual DDL; never disable foreign_keys during normal data deletion. R2 targets and pass/completion chains remain until the maximum45-day-or-later purge deadline; pending passes never expire. Full deletion manifest equals registry families plus browser memory/caches, provider retention disclosure and independent recovery ledger families.

Financial export after detailed90-day cost retention reports costState=expired and actualCostMicroUsd=null unless retained attributable usage supports a clearly labeled historical estimate; never call purged cost zero. Current model policy manifests remain versioned in the repository.
